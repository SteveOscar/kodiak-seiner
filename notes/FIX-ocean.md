# FIX-ocean — QA fix log (WP-OCEAN)

- [10]/[11]/[18] Reflection framebuffer incomplete after resize / dynamic resolution. Cause: three r186 `RenderTarget.setSize` resizes only colour; the water surface samples `uReflDepth` every frame, so the disposed DepthTexture was re-uploaded (immutable texStorage2D) at its old image size before the target was rebound -> FRAMEBUFFER_INCOMPLETE_DIMENSIONS forever. Fix: `reflection.resize()` (src/world/water/reflection.js) now replaces the depth texture with a new one at the new size (no-op when the size is unchanged), `render()` re-syncs to the drawing buffer too; `water.js` `resizeReflection()` repoints `uReflDepth`, zeroes `uRefl.x` and invalidates the cached image; `uReflDepth` is also re-read after every render. Added `water.qaPasses.reflectionStatus()` (checkFramebufferStatus + attachment sizes). Verified: `qa/fix-ocean/resize.json` (setPixelRatio 0.875 -> 1.0 -> 1.5, then 1.25 at night while the pass is idle) --strict: before 257 warnings + dark water (qa/fix-ocean/resize-before), after 0 warnings, FB complete at every step, mirrored hills in every shot (qa/fix-ocean/resize-after/p0..p3).
- [9] Pale blotchy edge bands. Main cause in the evidence runs was [10] (all four evidence runs had the FB flood: interior mixed toward the dead black image, edges fell back to kSky; reproduced in resize-before/p2). Also removed the hard in/out test in src/world/water/glsl.js: lookups fade over the outer 2% of the image (`inside`) with the UV clamped half a texel in, and the reflection pass renders with a 6% guard band (`REFLECTION_GUARD` in reflection.js; target grows by the same factor so on-screen texel density is unchanged; camera.zoom folded into the fov).
